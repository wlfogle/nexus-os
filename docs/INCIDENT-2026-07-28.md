# Incident Resolution Log — 2026-07-28
> Issues reported 2026-07-24, resolved 2026-07-28.

## Issues Reported

1. OpenWrt WebUI inaccessible at `http://192.168.12.222:8101/`
2. `riven-jd2-bridge.service` failing (TOKEN_INVALID / No MyJDownloader devices)
3. Cockpit not loading CT-300 or Proxmox host

## Root Causes & Fixes

### 1. OpenWrt WebUI (:8101)
**Cause:** uhttpd never listened on port 8101. WAN firewall zone had `input=REJECT`, blocking all inbound connections including port 80.
**Fix:**
- Added firewall rule: allow HTTP/HTTPS from `192.168.12.0/24` on WAN zone
- Added port 8101 to uhttpd listen list: `uci add_list uhttpd.main.listen_http='0.0.0.0:8101'`
- WebUI now accessible on both `:80` and `:8101`

### 2. riven-jd2-bridge (TOKEN_INVALID → No devices)
**Cause:** JDownloader2 had not run since 2026-05-05. `default-jre-headless` (Java) was not installed on Tiamat, so JD2 could not start. Without JD2 running, no device appeared on MyJDownloader cloud, causing `TOKEN_INVALID` from stale session tokens and then `No MyJDownloader devices online`.
**Fix:**
- Installed `default-jre-headless` (OpenJDK 21) on Tiamat via apt-get
- Created `/etc/systemd/system/jdownloader2.service` (Type=simple, DISPLAY=:1, Restart=on-failure)
- JD2 auto-updated on first run (~10 min init), then registered as `mediastack-jd2` on MyJDownloader
- Restarted `riven-jd2-bridge` → connected immediately, now processing downloads

**JD2 service file:** `/etc/systemd/system/jdownloader2.service`
```
[Unit]
Description=JDownloader2
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=root
Environment=DISPLAY=:1
ExecStart=/usr/lib/jvm/java-21-openjdk-amd64/bin/java -jar /root/JDownloader2/JDownloader.jar
WorkingDirectory=/root/JDownloader2
Restart=on-failure
RestartSec=10

[Install]
WantedBy=multi-user.target
```

### 3. Cockpit not loading CT-300 / Proxmox host
**Cause 1 (Tiamat):** `cockpit.socket` on Tiamat had been inactive since 2026-07-22.
**Fix:** `systemctl enable --now cockpit.socket` on Tiamat.

**Cause 2 (CT-300):** CT-300 (`192.168.12.30`) was not in the laptop's Cockpit machines config.
**Fix:** Added entry to `/etc/cockpit/machines.d/99-webui.json`:
```json
"192.168.12.30" : {
  "visible" : true,
  "color" : "#3584e4",
  "user" : "root",
  "address" : "192.168.12.30"
}
```
